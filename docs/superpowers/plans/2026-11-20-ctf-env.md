# Environnement CTF : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** une commande `ctf` qui range chaque challenge, y dépose automatiquement les téléchargements, connecte le VPN HTB, et des noms impacket qui marchent.

**Architecture:** un script Python unique `ctf` (bibliothèque standard), dont `ctf watch` tourne dans un service systemd utilisateur. `install.sh` pose les liens, le service, les noms impacket et la fonction zsh `cdc`.

**Tech Stack:** Python 3.14, systemd utilisateur, openvpn, notify-send, zsh, unittest.

**Spec:** `docs/2026-11-20-ctf-env-design.md`

## Global Constraints

- Dépôt `~/Documents/ctf-env`, commits sans ligne `Co-Authored-By`.
- Python bibliothèque standard uniquement, aucun nouveau paquet système.
- Challenges dans `~/Documents/ctf/<groupe>/<nom>/` ; noms `^[a-z0-9][a-z0-9-]*$` pour le groupe et le nom.
- Ne jamais déplacer ni modifier les fichiers déjà présents dans `~/Documents/ctf` ou `~/Downloads`.
- Textes en français, accents compris, sans tiret cadratin.
- Chemins surchargeables par variables d'environnement pour les tests : `CTF_ROOT` (défaut `~/Documents/ctf`), `CTF_CONFIG` (défaut `~/.config/ctf`), `CTF_CACHE` (défaut `~/.cache/ctf`), `CTF_DOWNLOADS` (défaut `xdg-user-dir DOWNLOAD`, sinon `~/Downloads`).
- Désinstallation pip : liste exacte montrée à l'utilisateur et validée avant toute commande.

## Review Focus

1. Challenge en cours supprimé à la main (lien `.courant` cassé) : `ctf` le signale, le service ne déplace rien et ne plante pas. (Tâche 2, `test_broken_current_moves_nothing` ; Tâche 1, `test_status_broken_current`)
2. Fichier encore en cours d'écriture sans extension temporaire (copie lente, `wget`) : pas déplacé tant que sa taille change. (Tâche 2, `test_waits_until_size_stable`)
3. Nom déjà présent dans `fichiers/` : rien n'est écrasé. (Tâche 2, `test_collision_suffix`)
4. `ctf new` sur un challenge existant : ne réécrit pas `notes.md`, le rend simplement en cours. (Tâche 1, `test_new_existing_keeps_notes`)
5. `ctf vpn` alors qu'une connexion tourne déjà : ne lance pas un second openvpn. (Tâche 3, `test_vpn_already_running`)

### Task 2: Rangement des téléchargements

**Files:** Modify `ctf`, `tests/test_ctf.py` ; Create `ctf-downloads.service`

**Interfaces:**
- Consumes: `paths()`, `current()`.
- Produces:
  - `class Watcher` : `__init__(self, now: float)` mémorise les noms déjà présents (jamais déplacés) ; `tick(self, now: float) -> list[tuple[Path, Path]]` renvoie les déplacements faits.
  - `free_name(dir: Path, name: str) -> Path` : `a.zip`, `a (2).zip`, `a (3).zip`...
  - `ctf watch` : boucle `tick` toutes les secondes, `notify-send` pour chaque déplacement (échec ignoré).
- Règles : ignorer les noms cachés et les suffixes `.crdownload .part .tmp .download` ; déplacer un fichier quand sa taille est identique depuis au moins 2 s ; `.ovpn` vers `config/vpn/` ; sans challenge en cours, ne rien déplacer et marquer le fichier comme vu (un fichier arrivé hors challenge reste dans `~/Downloads` pour toujours) ; dossiers ignorés.

- [ ] **Step 1: tests** (horloge passée en argument, pas de `sleep`)
  - `test_existing_files_never_moved`
  - `test_moves_new_file_after_stable` : apparu à t=0, rien à t=1, déplacé à t=2,5 dans `fichiers/`.
  - `test_waits_until_size_stable` : taille qui change à chaque tick → jamais déplacé tant qu'elle change.
  - `test_ignores_partial_and_hidden`
  - `test_ovpn_goes_to_config`
  - `test_collision_suffix`
  - `test_no_current_moves_nothing` : arrivé sans challenge en cours, toujours pas déplacé après activation d'un challenge.
  - `test_broken_current_moves_nothing`
- [ ] **Step 2: échec attendu**
- [ ] **Step 3: implémenter `Watcher`, `free_name`, `watch` ; écrire `ctf-downloads.service`** (`ExecStart=%h/.local/bin/ctf watch`, `Restart=on-failure`, `WantedBy=default.target`)
- [ ] **Step 4: tests au vert**
